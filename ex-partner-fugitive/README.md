# 我的前任是逃犯 · 私人加密阅读器

静态站点，无后端、无依赖。部署路径：

```
https://yuanmenghe.github.io/Demo/ex-partner-fugitive/
```

> 按站主要求，本子站**不**加入 Demo 站点的 Hub 导航页，仅通过直链访问。

## 目录结构

| 文件 | 说明 |
|------|------|
| `index.html` | 阅读器外壳：密码门、顶栏、目录抽屉、正文容器 |
| `assets/app.css` | 全部样式（含深/浅色主题、响应式、打印样式） |
| `assets/app.js` | 解密、目录、主题、字号、进度条、灯箱等交互 |
| `assets/content.bin` | **加密后的正文**（JSON 封装，AES-256-GCM） |
| `assets/img/` | 13 张配图（由原始导出重命名，已内嵌尺寸避免布局跳动） |

## 内容如何保护

正文不直接出现在 HTML 里，而是以加密形式存放于 `assets/content.bin`：

- 密钥派生：`PBKDF2-HMAC-SHA256`，310,000 次迭代，每份内容独立随机 16 字节 salt
- 加密算法：`AES-256-GCM`（12 字节随机 IV + 16 字节认证标签），GCM 认证保证密文无法被静默篡改
- 解密时机：仅在用户提交密码后才 `fetch` 内容包并在浏览器本地解密，明文只存在于内存与 DOM 中，不写回磁盘

`content.bin` 中**只有**密文与解密参数（salt / IV / tag / 迭代次数），书名与章节清单也一并加密在内——不输入密码就读不到目录。

**安全边界（请如实告知访问者）**：GitHub Pages 是公开静态托管，正文密文与图片文件本身仍可通过仓库获取。本方案的价值在于"正文不落明文、密码不上传服务器"，而不是防御有仓库读权限的人。若需更强保护，请勿将内容发布到公开仓库。另需注意：图片未加密，知道直链即可直接访问 `assets/img/`。

## 重新生成内容包

原始素材为思源（SiYuan）导出的 `index.html`。构建脚本（不在本仓库内，避免密码进入 git 历史）会：

1. 用 `parse5` 解析导出的 DOM，切分章节、剥离思源私有属性（`protyle-*`、`data-type`、`contenteditable` 等）
2. 重命名并内联 13 张图片（含 2 张原本热链的远程图），写入 `width`/`height`
3. 将每章文末的「版权声明」合并为紧凑浅色区块；把每章重复的「这是合集：…」提示降级为弱化的纯文本行（去除公众号跳转链接）
4. 在对应段落插入「查证备注」——基于公开资料检索的外部交叉验证，均带来源链接与检索日期，并明确标注为非原文内容
5. PBKDF2 + AES-256-GCM 加密后写入 `assets/content.bin`

## 换密码

改构建脚本的环境变量 `SITE_PASSWORD` 后重新生成 `assets/content.bin` 并推送，旧密码立即失效。
